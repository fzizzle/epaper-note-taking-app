# Jot project review · 20 November 2026

Reviewed commit `fe4a855`. This is a source review of the notes app, the input probe, their Android build configuration, relevant JVM and device tests, and the project documentation. No build, test suite or tablet measurement was run. Locations below are repository-relative. For Kotlin references, `app/` abbreviates `notes/app/src/main/java/com/fzizzle/epapernotes/` and `test/` abbreviates the corresponding `notes/app/src/test/java/com/fzizzle/epapernotes/` directory. Rankings prioritize loss of user files over interaction and maintenance costs.

## Confirmed from source

1. **High · An external edit during autosave can be overwritten.** In `app/doc/DocumentSession.kt:851–867`, Jot checks the destination, writes the full temporary PDF, then fingerprints the temporary file and records the pending save. If sync replaces the destination during that write, the final rename in `app/storage/SafeSave.kt:65–66` replaces the incoming version. This violates the two-version promise in `README.md:58`. Add a regression that replaces the destination from the fake PDF writer and asserts that both versions survive. Revalidate the destination after writing and route conflicts through copy recovery. A final check still leaves a narrow rename race with uncoordinated writers. To guarantee preservation, use a publication protocol that retains the displaced file, or narrow the documented guarantee on storage without suitable primitives.

2. **High · Creating a fresh copy can replace someone else's file.** Fresh attempts call `SafeSave.createNew` at `app/ui/LibraryChanges.kt:110`. Its existence check at `app/storage/SafeSave.kt:80–83` precedes a replace-existing move at line 66. A sync client can claim the same name between those operations. The existing arrival test creates its destination *inside the writer*, before the check (`test/storage/SafeSaveTest.kt:134–137`). Split create-only publication from replacement. Use a filesystem-supported exclusive operation and verify behavior on both internal storage and the supported SD card. Exercise a competing creator at publication and assert that its bytes survive.

3. **High impact, conditional on journal damage · Recovery can discard an intact edit.** `app/doc/ChangeJournal.kt:267–284` omits undecodable changes from the returned list. `app/doc/DocumentSession.kt:182–185` then drops a count measured in the original list. For example, if A and B were saved, C was appended later, and A's picture is damaged, recovery sees B and C and drops both. C can be fully readable and absent from the PDF. Preserve change ordinals through decoding, or persist an explicit save boundary identifying the saved records. Keep the original journal when recovery is ambiguous. Combine the damaged-picture case in `test/doc/ChangeJournalTest.kt:329–338` with a matching pending-save result and an independent later stroke.

4. **Medium · An unreadable library looks empty.** `app/library/FolderListing.kt:32–43` returns an empty list when the directory cannot be listed, and assigns unreadable children zero counts. `app/ui/LibraryActivity.kt:517–522` passes the selected directory into that API, which gives the caller no failure signal. After an SD-card access failure the owner can reasonably think the PDFs disappeared. Return a distinct read failure, retain the last successful listing where available, and offer retry. Test a failed listing alongside a genuinely empty directory.

5. **Medium · Erasing lacks feedback during a drag and the settled redraw can flash.** The owner recorded both symptoms in `TODO.md:64–70`. The implementation already groups redraws and transfers pen input during the pause (`app/ui/WritingActivity.kt:1792–1829`). Preserve those behaviors in any experiment. On the tablet, compare isolated erases, a continuous hover-button drag and immediate pen-down after erase. Record flashes per gesture, time until erased ink disappears and whether the next stroke retains its first point. Assess transient feedback on both the hover and Onyx erase routes before changing the waveform.

6. **Low · The README overstates page preservation.** `README.md:53–60` promises that the original page is never changed immediately after describing persisted page rotation. Explain that ordinary handwriting adds annotations over existing page content, while explicit page operations can change the PDF's pages. Also align the status at `README.md:11` with the settled-run flash described in `TODO.md:70` and distinguish that flash from the requested drag feedback.

## Ideas requiring measurement or design validation

7. **Medium · Measure journal cost at pen lift.** Commit holds the session lock across journal append at `app/doc/DocumentSession.kt:464–485`; each append completes a synchronous flush at `app/doc/ChangeJournal.kt:308–315`. Capture p50 and p95 for lift-to-return and next-stroke acceptance during fast handwriting and large snip edits. The code establishes a blocking operation, but its perceptible cost on this tablet is unknown. Preserve the existing crash-durability boundary in any optimization. For measurements using the probe, account for synchronous per-event file logging at `probe/app/src/main/java/com/fzizzle/epapernotes/probe/ProbeLog.kt:26–32`.

8. **Medium · Give one component ownership of pen handoff during redraw.** Sharp zoom, ordinary redraw and erase settling all coordinate delayed work, current pen state and panel updates in `app/ui/WritingActivity.kt:1756–1778` and `app/ui/WritingActivity.kt:1792–1835`. Extract that transition logic behind a fake clock and pen adapter when next changing it. Exercise pen-down during pause, pen-up during deferral and a newer redraw arriving before resume. This is a maintainability proposal; the reviewed handoff already contains safeguards for these transitions.

9. **Low · Verify both Gradle downloads.** Both `notes/gradle/wrapper/gradle-wrapper.properties:3` and `probe/gradle/wrapper/gradle-wrapper.properties:3` pin the Gradle version by URL. Add the matching distribution checksum to each wrapper and validate a clean build of both modules when upgrading. The separate probe can then reproduce its build with the same archive verification as the shipping app.
