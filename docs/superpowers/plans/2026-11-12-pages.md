# Dotted Pages and Fresh Attempts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** From any page, add a page of dotted paper after it, for working that doesn't fit on the slide; and from the library, make a clean copy of a workbook, without the ink, to try it again.

**Architecture:** A dotted page is an ordinary new page in the PDF, drawn with plain PDF drawing commands, so every other viewer shows it. Adding one changes every later page's number, so it is not a journaled, undoable change like ink: the session first writes everything pending into the PDF, adds the page, saves through the usual safe replace, and the screen lays the document out again. A fresh attempt is a copy of the file with the app's own items removed, made in the library by the same safe write.

**Tech Stack:** As now: Kotlin, MuPDF 1.28.5 (`PDFDocument.addPage`, `insertPage`, `deletePage`). Nothing new.

**Spec:** `docs/superpowers/specs/2026-11-07-epaper-pdf-notes-design.md` §3 (blank notebooks stay a non-goal: this adds pages to an existing PDF, not notebooks), §4 (lost writing is the worst failure), §6.2 (strip and ⋯ menu), §6.1 (long-press menu), §7.2–7.3 (saving), §8 ("the page and ink model shouldn't assume every page comes from an existing PDF").

**Owner's words (2026-11-12):** the add-a-page feature "available for every page", and "I want the page to be dotted paper"; "the fresh attempt feature is good".

Paths below are under `notes/app/src/`. `main/…` means `main/java/com/fzizzle/epapernotes/…`, `test/…` and `androidTest/…` likewise.

## Decisions for the owner (approve before Task 1)

1. **Where it's reached.** ⋯ gets "Add a dotted page after this one", on every page. On the last page, the greyed-out › becomes **+**, which does the same.
2. **The paper.** The same size and way up as the page it follows. Dots 5 mm apart, about 0.4 mm across, mid grey. Task 5 puts two strengths on the tablet for you to pick from.
3. **Adding a page can't be undone with Undo, and it empties the undo list.** Every later page's number changes, and the undo list is kept by page number. Instead, ⋯ shows "Remove this added page" on a page the app added (never on the PDF's own pages), and asks first if it has writing on it.
4. **Adding a page saves the file at once.** If the file can't be saved into right now (it was changed elsewhere, or it's a damaged file waiting for your answer), the page isn't added and a message says why.
5. **Fresh attempt.** Long-press a PDF in the library, "Fresh attempt": a copy beside it named `<name> (attempt 2).pdf` (then 3, 4, …), with your ink and pasted snips removed. Dotted pages you added stay, empty. Marks made in other apps stay. The original isn't touched. The library stays where it is and the new tile appears.

## Global Constraints

- "Every stroke must survive a crash, kill, or power loss from the moment the pen lifts" (spec §7.3). A page is added only after everything recorded so far is in the PDF, and through `SafeSave.replace`, so a kill at any moment leaves either the old file with its journal or the new file.
- "The PDF on disk must never be left half-written" (spec §7.3). "Annotations the app didn't create … must be kept intact on save" (spec §7.1). "The original page content is never modified" (spec §2.3).
- fitz 1.28.5: never `PDFObject.push(PDFObject)` or `addObject` (a refcount bug crashes the app later). `test/pdf/NoRefcountTrapsTest` must still pass. Task 1 checks `addPage`/`insertPage`/`deletePage` on the tablet before anything is built on them.
- All MuPDF access on the document's single worker thread. `doc/` stays free of Android and MuPDF types (tests use `FakePdfPages`).
- No new libraries. Readable code: small files, plain names, comments that say why.
- Toolchain: `source ~/.local/opt/android-env.sh`; laptop tests `./gradlew :app:testDebugUnitTest`; tablet tests `./gradlew :app:installDebug :app:installDebugAndroidTest`, then `adb shell am instrument -w -e notPackage com.fzizzle.epapernotes.check com.fzizzle.epapernotes.test/androidx.test.runner.AndroidJUnitRunner`; release build back afterwards. Never `git add -A`. Tablet checks only on copies or a scratch folder, never the owner's Workbooks.

## Review Focus

1. **A stroke finished in the instant before "Add a dotted page".** It lands on the page it was written on, not one page along (Task 4: `aStrokeRecordedJustBeforeStaysOnItsPage`).
2. **The app is killed while a page is being added.** At the next opening the file is whole, either without the page or with it, and no stroke is lost or on the wrong page (Task 4: `aKillWhileAddingLosesNothing`).
3. **A page added after a rotated page.** It is the size and way up the rotated page is shown, not sideways (Task 3: `anAddedPageMatchesARotatedNeighbour`).
4. **A fresh attempt of a file that is open or still saving its last strokes.** It waits for that save, so the copy is made from the finished file (Task 6: `aFreshAttemptWaitsForTheLastSave`).
5. **A fresh attempt of a PDF holding another app's highlights.** They are still there; only the app's own ink and snips are gone (Task 6: `aFreshAttemptKeepsOtherAppsMarks`).
