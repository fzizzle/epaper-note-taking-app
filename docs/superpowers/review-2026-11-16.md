# Review of 2026-11-16

A read-through of the whole app for bugs, as it stands on `main` after PR #30 (acf77cb), with suggestions for improvement. Four passes: the saving and conflict code, the PDF and journal code, the writing screen, the library. **Nothing was run on the tablet**: every row below comes from reading the code, and the "How sure" column says how far each was traced.

No way was found to lose handwriting in normal use. The bugs are in rare situations: a full tablet, a file changed elsewhere, the screen being rebuilt by Android.

Each row has a plan. Play Store findings from the same day are in their own file: [play-store-findings.md](play-store-findings.md).

Paths are under `notes/app/src/main/java/com/fzizzle/epapernotes/`.

## B. The writing screen

Plan: [screen and library fixes](plans/2026-11-16-screen-and-library-fixes.md).

**Fixed on branch `screen-library-fixes` (2026-11-16): B1 to B4, B6 and B7. B5 is checked and its fix waits on the owner's pen check.** The owner checklist is still open: [notes/TESTING-review-2.md](../../notes/TESTING-review-2.md).

- B1 fixed: the copy's path is saved with the screen's state and read first, so a rebuilt screen reopens the copy.
- B2 fixed: a keyboard or page-turner and dark mode no longer rebuild the screen (the manifest handles them). A change of font size or display size still rebuilds it (decision 2), and the rebuilt screen comes back to the right file.
- B3 fixed: a page picture that runs out of memory is dropped and asked for again.
- B4 fixed: a paste or a selection moved past the page is pushed back onto it.
- B5 checked, not fixed: on the tablet the notification shade and the power menu take focus while fast-ink stays on. Whether the pen marks the page through them waits on the owner's pen check; the fix (pause fast-ink there) follows if it does.
- B6 fixed: windows are counted, so fast-ink returns only when the last one closes.
- B7 fixed: a question is not shown on a screen already taken down.

## Noted, not planned

From the passes, smaller or less sure than the rows above. None has a plan.

- A stroke cut short by a pause (a dialog opening mid-stroke) is dropped; its points could be kept from `onRawDrawingTouchPointMoveReceived`.
- `StrokeCodec` would write and read back a point that isn't a number (NaN); `Stroke` could refuse one.
- `Scheduler`: a delayed task accepted just before shutdown still runs up to 30 s later. Harmless today, since the session has let go of the PDF by then.
- If another app moves one of Jot's strokes, it probably rewrites the drawing but not Jot's own record of the points, so the eraser and lasso would act on the old place.
- A memory card pulled out isn't noticed until the library is next resumed.
- While a library change waits up to 15 s for a save, long-presses are ignored with no sign.
- The thumbnail cache has no size limit; `FolderListing` reads every subfolder on each listing.
- Tablet tests worth adding: a PDF with an owner password only, a page with `/UserUnit`, one stroke of 5,000 points or more through save and reopen.
