# UI Review Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix what the UI and UX review of 2026-11-12 found: twin tiles that can't be told apart, a writing screen that doesn't say which file is open, tools that move when Paste appears, menus with no edges, oversized folder tiles, and a few smaller rough edges.

**Architecture:** Six independent tasks, each a small change to the library's tiles or the writing strip, then an owner checklist. Only two new pieces of logic, both pure and tested on the laptop: the short tile names (`library/TileNames.kt`) and where the strip puts the file name (`StripPlacement` in `ui/CentredStrip.kt`). The rest is drawing and theming, checked with screenshots on the tablet.

**Tech Stack:** As before: Kotlin, Android views drawn by hand, JUnit 4 on the laptop. One new resource file for the theme. Nothing else new.

**Spec:** `docs/superpowers/specs/2026-11-07-epaper-pdf-notes-design.md` §6.1 (library), §6.2 (writing strip), §6.3 (copy, delete, paste), §11 (designer's decisions). Earlier UI notes: `docs/superpowers/ui-feedback.md`.

Paths below are under `notes/app/src/`. `main/…` means `main/java/com/fzizzle/epapernotes/…`, `test/…` likewise.

## What the review found (2026-11-12, on the tablet)

1. The workbook and the answer key show the same first page, and their names are cut off where they differ ("BSA Degree of Hyperstaticity — answer …" / "— workbo…"). The writing screen never shows the file's name.
2. Paste joins the island after a copy or snip, and the centred island shifts every tool about 40 px to the left.
3. The long-press menu and the ⋯ menu are Android's stock menus: an off-white panel with a shadow e-ink can't show, so they have no visible edge. The long-press menu doesn't show which tile it's for. Ticks, the text field line and the text selection are teal, the only teal in the app.
4. ⋯ puts "Rotate all pages", which rewrites the PDF, right above three settings that only change the screen.
5. Folder tiles are square boxes holding an outline, about 520 px tall for a name and "2 PDFs". Two-line names touch the count under them; one-line names leave a gap.
6. "Go to page" has its number against the dialog's left edge.
7. The copy message ("Copied. To paste, hold a finger on the page, or tap Paste.") is two lines, every time.
8. The Paste bubble (finger long-press) is a little larger than the strip's buttons, with different corners.
9. The pen mark is wider than the black circle that picks it out, so its ends are cut.
10. Erasing gives no sign while dragging, and each erase flashes (both already in TODO.md).

## Decisions for the owner (approve before Task 1)

1. **PDF tiles leave out the part of the name they all share** (finding 1), but only when every PDF in the folder starts with the same text up to a dash or colon (" — ", " – ", " - ", ": "). "BSA Degree of Hyperstaticity — workbook" shows as "workbook". "Lecture 1" and "Lecture 2" stay whole: there's no dash. Folder tiles keep their full names. Rename still shows the full name.
2. **The writing strip shows the file's name**, in grey, to the right of ←. If it's too long, it's cut from the front, so the end stays ("…Hyperstaticity — workbook"). It's set once when the file opens, so it costs no flash. This adds an item to the strip in spec §6.2.
3. **Paste is always on the island**, greyed out until something is copied, like Undo and Redo with nothing to undo. The tools never move. This changes spec §6.3 and §11 ("Paste appears … only then"). The other way: Paste goes next to ⋯ at the right, where moving things matter less.
4. **Menus get a black outline, and teal becomes black everywhere.** ⋯ is split by a line into "Rotate this page / Rotate all pages" and the three look settings. The look settings stay in ⋯, because you judge them while looking at a page. The tile you long-pressed stays grey while its menu is open.
5. **Folder tiles get shorter**: a small folder mark instead of a square box, so a course's 20 topics fit in about 60% of the height. It's still a grid, as spec §6.1 says. The other way is a plain list of folders like the Move window, with the grid kept for PDFs: clearer, but a bigger change to the library screen.
6. **The copy message is shorter after the first three times**: "Copied." From then on, the grey-to-black Paste button is the sign.
7. **Left out of this plan:** the eraser's missing trail and its flash (finding 10) need their own plan, since they're about how Onyx draws, not the layout. A mark on files you've written in is a new feature nobody has asked for yet. The pen mark stays a stroke; it only shrinks to fit (finding 9).

A decision left unapproved drops its task. Tasks 1–6 don't depend on each other.

## Global Constraints

- Lightweight: no libraries, fonts, image files or animations (owner, 2026-11-09). Shapes drawn in code; one theme file and one shape drawable at most.
- While fast-ink is on, any redraw of the strip is a full-screen flash. The file name is set once at open; Paste changes only when the clipboard or arming changes, as it does today.
- No disk reads on the UI thread.
- Copy: sentence case, plain words, British spelling, active verbs. A button and the message after it use the same word.
- Colours: black, white, the existing greys (`LibraryLook.RULE` = rgb 200, `LibraryLook.GRAPHITE` = rgb 77), and the highlighter yellow. No new colours.
- Branch: `ui-review`, from `main` at or after 50fdf56 (PR #22 merged, 2026-11-12). Line numbers in this plan are from that commit. Never `git add -A`: the owner sometimes runs a second session in the same checkout.
- Toolchain: `source ~/.local/opt/android-env.sh`, then from `notes/`: laptop tests `./gradlew :app:testDebugUnitTest`. On the tablet: `./gradlew :app:installDebug` (it installs over the release build and keeps the app's data). Check the tablet is quiet before installing (`adb shell dumpsys activity activities | grep topResumedActivity`). Put the release build back at the end (`./gradlew :app:installRelease`).
- Screenshots: `adb exec-out screencap -p > shot.png`. Taps are `adb shell input tap x y` on the 1860 × 2480 screen. `adb shell input stylus swipe …` reaches the app only while fast-ink is off (snip, selection, paste). Wake the tablet with `adb shell input keyevent WAKEUP` first.
- Try things only in the owner's test copy (`/sdcard/Documents/E-paper Notes test/`), never in the Workbooks on the SD card. Open it with `adb shell "am start -n com.fzizzle.epapernotes/.ui.LibraryActivity --es path '/sdcard/Documents/E-paper Notes test/PWT test copy.pdf'"` (debug build only).

## Review Focus

1. **A very long file name in portrait.** It never reaches the island, and the island stays centred (Task 3: `aLongNameGetsOnlyTheRoomLeftOfTheIsland`).
2. **A folder of numbered PDFs** ("Lecture 1", "Lecture 2", "Lecture 10") keeps full names (Task 1: `numberedNamesAreLeftWhole`).
3. **A workbook next to its saved copy** ("X — workbook" and "X — workbook (my edits 2026-11-12)") shows "workbook" and "workbook (my edits 2026-11-12)", not two identical labels (Task 1: `aCopyKeepsWhatSetsItApart`).
4. **The island in portrait, now always one button wider.** All buttons stay at full size, and the name still gets room (Task 4, tablet screenshot; Task 3: `theIslandWinsWhenThereIsNoRoom`).
5. **Long-press, then Rename.** The rename field shows the full name, not the short label, and the tile's grey mark goes when the menu closes, whether by a choice or a tap outside (Task 5, owner checklist U5).

### Task 2: Shorter folder tiles, with the count clear of the name (decision 5)

**Files:**
- Modify: `main/ui/LibraryTiles.kt` (`TileView.onMeasure`, `onDraw`, `drawFolder`)

- [ ] **Step 1: Measure folder tiles shorter.** In `onMeasure`, a `FolderEntry` tile is `pad + markHeight + pad / 2 + 2 * nameLine + countGap + countLine + pad`, with `markHeight = (boxSide * 0.4f).toInt()` and `countGap = pad / 2`. A PDF tile keeps its square box and adds nothing. GridView makes each row as tall as its tallest tile, so a row mixing the last folders and the first PDFs takes the PDF height.
- [ ] **Step 2: Draw the folder mark in that band.** `drawFolder` draws the same outline (body and tab, 3 px black) fitted to a box `markHeight` tall and `markHeight * 1.3f` wide, centred across the tile. The name starts at `pad + markHeight + pad / 2`.
- [ ] **Step 3: Put the count below the name's two lines with a gap**, `countGap` below the second line's slot for every folder tile, whether the name takes one line or two. All counts in a row then line up, and none touches its name.
- [ ] **Step 4: Check on the tablet.** Screenshot the ADVP folder (20 topics): all 20 fit with room to spare, and "From the Binomial Model to Black–Scholes" has a clear gap above "2 PDFs". Turn the tablet to landscape (or ask the owner to): 7 across, nothing cut off.
- [ ] **Step 5: Commit.** `git commit -m "library: folder tiles are a small folder mark, so a course's topics fit on one screen"`

### Task 3: The writing strip shows the file's name (decision 2)
