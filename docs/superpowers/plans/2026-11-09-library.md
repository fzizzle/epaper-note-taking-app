# Library Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the temporary start list with the library of spec §6.1: one folder at a time as a grid of folder tiles and first-page thumbnails, a breadcrumb, refresh and new-folder buttons, rename, move and delete on long-press, and a grid that follows changes on disk. Leaving a document becomes fast, because nothing scans the whole tree any more.

**Architecture:** Plain-Kotlin parts, unit-tested on the laptop: listing one folder (what's shown, in what order), the breadcrumb, the file operations (rename, move, delete, new folder, with the app's own per-file data moved along), and the thumbnail cache's keys and clean-up. The Android parts stay thin: a `LibraryActivity` with a `GridView`, one background thread for listing and one for thumbnails, and a `FileObserver` on the folder on show. The writing screen is unchanged apart from where "back" goes. The plan ends with an owner session on the tablet: a **hard stop**.

**Tech Stack:** As in plan 3 (Kotlin 2.0.21, AGP 8.7.3, compile/target SDK 35, min SDK 29, MuPDF `fitz:1.28.5`, Onyx `onyxsdk-pen:1.5.9`, JUnit 4.13.2). Nothing new. Only framework views (`GridView`, `PopupMenu`, `AlertDialog`).

**Spec:** `docs/superpowers/specs/2026-11-07-epaper-pdf-notes-design.md` §6.1 (library), §2.2 (the tree exactly as on disk), §7.3 (temporary files never show), §6.1 last page in app-private storage.

**Where this plan sits:** plan 4 of 5, built on the `tools` branch. Plan 5 adds conflict copies and crash replay onto a changed file.

Paths below are under `notes/app/src/`. `main/…` means `main/java/com/fzizzle/epapernotes/…`, `test/…` and `androidTest/…` likewise.

## Decisions for the owner (approve before Task 1)

1. **Root folder.** On first launch the app opens a simple folder chooser at the tablet's storage, with `Documents` suggested; the owner taps the folder that holds the notes and "Use this folder". The ⋯ menu in the library can change it later. The breadcrumb never goes above the root.
2. **Grid.** Folders first, then PDFs, each group sorted by name the way people expect ("Lecture 2" before "Lecture 10", upper and lower case mixed). Tiles are about 5 across in portrait and 7 in landscape. A PDF tile shows its first page with ink, and its name under it on up to two lines. A folder tile is a plain drawn folder shape with the name and how many PDFs are directly inside.
3. **"Continue".** At the root, a single slim row "▶ Continue: <last file>" sits above the grid (as on today's start list). It's only shown when that file still exists.
4. **Top bar.** One thin row like the writing strip: the breadcrumb on the left (`Documents › Year 2 › Physics`, tap a part to go up), then **refresh**, **new folder** and **⋯** (opens **Settings**) on the right. Drawn with plain shapes, no images.
5. **Long-press menu** on any tile: **Rename**, **Move**, **Delete**.
   - Rename keeps `.pdf` on files; names with `/`, a leading dot, or a name already in the folder are refused with a short message.
   - Move opens the same folder chooser as decision 1, limited to the root's tree; a folder can't be moved into itself.
   - Delete asks first and says what goes: "Delete 'Lecture 4.pdf'?" or "Delete folder 'Physics' and the 12 PDFs inside?". It deletes the real files (spec §6.1).
6. **The app's own data follows the file.** Renaming or moving a PDF (or a folder of them) also moves its remembered page and any unsaved journal, so no writing is stranded. Deleting a PDF deletes them too. A file whose writing screen is still saving waits for that save before it is renamed, moved or deleted (a second or two at most).
7. **Following the disk.** The folder on show is watched while the library is open (files added, removed, renamed or rewritten by a laptop, sync app or USB), and re-read a moment after things settle. It's also re-read whenever the library comes back on screen, and on **refresh**, which also redraws its thumbnails.
8. **Thumbnails** are drawn in the background, one at a time, 300 px wide, and kept as small PNGs in the app's cache. A thumbnail is redrawn only when its file's size or modified time changes. Until it's ready, the tile shows a plain grey page. Cached thumbnails for files that no longer exist are cleared once a day at most.
9. **Hidden things** are never shown: names starting with a dot (which includes the app's temporary save files), and anything that's neither a folder nor a PDF.
10. **Settings** (owner's request, 2026-11-10): a small window from ⋯ with **Library folder** (change the root, decision 1) and **Show thumbnails** (on by default). With thumbnails off, PDF tiles are plain drawn pages with their names: nothing is rendered or cached, and the thumbnail thread never starts. The switch takes effect at once and is remembered (app-private).
11. **The temporary start list is removed.** The `adb … --es path <pdf>` shortcut for checks moves to the library.

## Global Constraints

- "PDFs live in the owner's folder tree, and the app reflects that tree exactly, including changes made outside the app" (spec §2.2). "The grid updates automatically when files change on disk … and refresh forces a rescan" (spec §6.1).
- "Long-press a tile for a small menu: rename, move, delete. Delete asks for confirmation, because it deletes the real file." (spec §6.1)
- "Thumbnails are cached in the app's own cache storage and regenerated only when a file changes, so the grid stays fast." (spec §6.1)
- "Tapping a PDF opens it at the page where it was last left." The position stays "in the app's private storage, never in the owner's folders" (spec §6.1).
- "Temporary files must not show up in the library grid" (spec §7.3). Use `SafeSave.isTempFile`, and hide every dot-name.
- "Writing is never lost" (spec §2.6, §4): a rename, move or delete never strands or drops a journal by accident, and never runs while that file's session is still saving.
- Lightweight and fast on e-ink: no libraries, image files, fonts or animation; no work on the UI thread that touches more than one folder; framework views only (owner, 2026-11-09).
- Only MuPDF code lives in `pdf/`. Readable code: small files, plain names, comments that explain *why* (spec §5). The owner declined splitting `WritingActivity.kt` for now: touch it as little as possible.
- Toolchain: `source ~/.local/opt/android-env.sh`; Gradle in `notes/`. JVM: `./gradlew :app:testDebugUnitTest`. Tablet: `./gradlew :app:connectedDebugAndroidTest` (uninstalls the app; restore with `adb shell appops set --uid com.fzizzle.epapernotes MANAGE_EXTERNAL_STORAGE allow`). The owner may be using the tablet: wait for a quiet minute (`adb logcat -d -s Notes | tail`) before installing or running tablet tests. Never touch the owner's files except in a scratch folder the test creates and removes.

## Review Focus

1. **Renaming a file whose journal still holds unsaved writing** (a save that failed earlier). The writing must open with the file under its new name (Task 3: `renameMovesJournalAndLastPage`).
2. **Leaving a document and renaming it at once**, while its session is still saving. The rename waits; the save lands in the right file (Task 3: `renameWaitsForTheOpenSession`).
3. **A sync app replaces a PDF while its tile is on screen.** The thumbnail is redrawn, not the stale one kept (Task 4: `changedFileGetsANewThumbnail`).
4. **A folder of 300 PDFs.** The grid shows at once with grey tiles, thumbnails fill in without blocking scrolling, and leaving a document is fast (Task 6: timing logs; Task 7: owner check).
5. **Odd names**: spaces, accents, a dot inside ("v1.2 notes.pdf"), "PDF" in capitals, very long names (Task 1: `oddNamesAreListed`).

### Task 1: Listing one folder, and the breadcrumb

**Files:**
- Create: `main/library/FolderListing.kt`, `main/library/Breadcrumb.kt`, `main/library/NaturalOrder.kt`
- Test: `test/library/FolderListingTest.kt`, `test/library/BreadcrumbTest.kt`, `test/library/NaturalOrderTest.kt`

**Interfaces:**
- Produces:
  - `sealed interface Entry { val file: File; val name: String }` with `data class FolderEntry(override val file: File, override val name: String, val pdfCount: Int) : Entry` and `data class PdfEntry(override val file: File, override val name: String /* without .pdf */, val size: Long, val modified: Long) : Entry`.
  - `object FolderListing { fun list(folder: File): List<Entry> }`: one folder only, never recursive. Folders first, then PDFs (`.pdf` in any case), each by `NaturalOrder`. Hides every name starting with `.` (so `SafeSave` temp files too) and anything else. A folder's `pdfCount` counts PDFs directly inside, not deeper. An unreadable folder lists as empty.
  - `object NaturalOrder : Comparator<String>`: case-insensitive, digit runs compared as numbers ("Lecture 2" < "Lecture 10"), ties broken by the plain string so the order is stable.
  - `object Breadcrumb { fun parts(root: File, folder: File): List<Pair<String, File>> }`: from the root (named after its own folder) down to `folder`. A folder outside the root gives just the root.

### Task 2: Thumbnail cache

**Files:**
- Create: `main/library/ThumbnailCache.kt`
- Modify: `main/pdf/PdfFile.kt` (only if a smaller first-page render than `render(0, width)` is needed — it isn't expected)
- Test: `test/library/ThumbnailCacheTest.kt`, `androidTest/library/ThumbnailRenderTest.kt`

**Interfaces:**
- Produces:
  - `class ThumbnailCache(dir: File, private val clock: () -> Long = System::currentTimeMillis)`:
    - `fun fileFor(pdf: PdfEntry): File`: `<dir>/<sha256 of the canonical path, 16 hex>-<size>-<modified>.png`. A changed file gets a new name, so a stale thumbnail is never shown.
    - `fun cached(pdf: PdfEntry): File?`: the file if it exists.
    - `fun store(pdf: PdfEntry, png: ByteArray)`: written through a temp file and renamed; deletes older thumbnails of the same path (same hash prefix).
    - `fun pruneMissing(isLive: (hashPrefix: String) -> Boolean)`: at most once a day (`clock`, last run kept in a file in `dir`), deletes thumbnails whose source is gone.
  - Rendering stays outside: Task 5 renders with `PdfFile.open(file).use { it.render(0, THUMB_WIDTH_PX) }` and PNG-encodes the bitmap. `const val THUMB_WIDTH_PX = 300`.

### Task 3: File operations that carry the app's data along

**Files:**
- Create: `main/library/FileOps.kt`
- Modify: `main/doc/ChangeJournal.kt` (a `journalFileFor(journalDir, pdf): File` helper if `forDocument` doesn't already expose the file), `main/doc/DocumentSession.kt` (`companion fun awaitClosed(pdf: File, timeoutMs: Long): Boolean` on the existing `openSessions` gate), `main/ui/LastPageStore.kt` (`move(from, to)`, `remove(path)`)
- Test: `test/library/FileOpsTest.kt`

**Interfaces:**
- Consumes: `ChangeJournal.forDocument`, `DocumentSession` gate, `LastPageStore`.
- Produces: `class FileOps(private val root: File, private val journalDir: File, private val lastPages: PageMemory)` where `interface PageMemory { fun move(from: String, to: String); fun remove(path: String) }` (`LastPageStore` implements it; tests use a map):
  - `sealed interface Result { data object Done; data class Refused(val reason: String) }`, where `reason` is plain words for a toast.
  - `fun newFolder(parent: File, name: String): Result`
  - `fun rename(target: File, newName: String): Result` (files keep `.pdf`)
  - `fun move(target: File, into: File): Result` (refuses a folder into itself or its own subfolder, anything outside `root`, and a name already there)
  - `fun delete(target: File): Result` (a folder recursively)
  - `fun pdfCountInside(folder: File): Int` (recursive, for the delete question)
  - Every PDF affected (the file, or every PDF under a folder) first waits for its session: `DocumentSession.awaitClosed(pdf, 15_000)`; if that times out, `Refused("… is still saving. Try again in a moment.")`. Then, for each affected PDF, its journal file and last-page entry move to the new path (rename/move) or are deleted (delete). The disk operation goes first; the app data only moves if it succeeded.
  - Name rules: not blank, no `/`, no leading `.`, no existing name in that folder (case-insensitive, as FAT/exFAT cards are).

### Task 5: The library screen

Android-only, checked by hand (build, install, launch, screenshots with `adb exec-out screencap -p`; the owner checks by pen and finger in Task 7).

**Files:**
- Create: `main/ui/LibraryActivity.kt`, `main/ui/LibraryTiles.kt` (the grid adapter and the drawn tile), `main/ui/FolderChooser.kt` (the dialog for decisions 1 and 5), `main/ui/LibrarySettings.kt` (the settings window of decision 10, and the stored root folder and thumbnail switch)
- Modify: `main/ui/StripButton.kt` (glyphs `REFRESH`, `NEW_FOLDER`; reuse `MENU`), `AndroidManifest.xml` (launcher → `LibraryActivity`)
- Delete: `main/ui/DevStartActivity.kt` (its All-files-access prompt and the `--es path` shortcut move to `LibraryActivity`)

**Behaviour** (decisions 1–11):
- Listing runs on a single background thread (`FolderListing.list`), the grid is filled when it returns; nothing on the UI thread touches more than the folder on show.
- Thumbnails (only while **Show thumbnails** is on; when it's off, no render thread, no cache reads, plain page tiles): a second background thread renders missing ones for the tiles on screen first, then the rest of the folder, one at a time; a tile's bitmap is decoded from the cache PNG off the UI thread and kept in a small LRU (about 40 MB). Scrolling never waits for a render.
- `FolderWatch` follows the folder on show between `onStart` and `onStop`. `onResume` re-reads the folder. Refresh re-reads and drops that folder's cached thumbnails first.
- Tapping a PDF opens `WritingActivity` (which already opens at the last page); a double tap opens it once.
- Long-press → `PopupMenu` (Rename / Move / Delete) → `FileOps` on the background thread → toast for `Refused` → re-read.
- Back at the root leaves the app; inside a folder it goes up one level.
- The library remembers the folder on show between visits (app-private).
